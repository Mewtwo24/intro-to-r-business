R Core: Syntax, Types, and Structures

An interleaved tutorial for reading, prompting, and testing R code

This tutorial is designed as a sequence of short experiments. Read the left column, copy the AI prompt into your approved assistant, paste the returned code into the editor on the right, and run it. The goal is not to memorize syntax. The goal is to predict what the code should do and then review whether it actually does it.

How to use each step

Each live panel is a complete small Shiny app. The setup creates a tiny business example; the marked transformation is the part you can replace with an AI-generated draft. After running it, compare the output with your prediction and record one thing you would verify in a real dataset.

Step 1: Assignment and data types

The Goal: Store business values under meaningful names and distinguish numeric, character, and logical data. Assignment uses <-; it does not mean that the two sides are mathematically equal.

The AI Prompt:

Create a short R example for a business analyst that assigns a numeric revenue value, a character region, and a logical target_met flag. Use typeof() and class() to inspect each object. Explain the output without changing the data.

What to look for: Look for clear names, <-, and values that match the intended type. An AI draft should not turn revenue into a character string or use a text value such as "yes" where a logical flag is required.

library(shiny)

revenue <- 125000
region <- "North"
target_met <- TRUE

ui <- fluidPage(
  titlePanel("Assignment and types"),
  mainPanel(verbatimTextOutput("details"))
)

server <- function(input, output, session) {
  output$details <- renderPrint({
    list(
      revenue = revenue,
      revenue_type = typeof(revenue),
      region = region,
      region_type = typeof(region),
      target_met = target_met,
      target_type = typeof(target_met)
    )
  })
}

shinyApp(ui, server)

Step 2: Vectors and indexing

The Goal: Represent a set of related values and select observations with positions, names, or logical conditions. R vectors are one-dimensional and usually contain one basic type.

The AI Prompt:

Generate an R vector of regional sales with named elements for North, South, East, and West. Show how to select West by name and how to filter regions whose sales exceed 100000. Explain why logical indexing is useful in business analysis.

What to look for: Look for c(), names attached with North =, and a logical condition such as sales > 100000. Check that the filter returns the values and labels you expect.

#| '!! shinylive warning !!': |
#|   shinylive does not work in self-contained HTML documents.
#|   Please set `embed-resources: false` in your metadata.
#| standalone: true
#| components: [editor, viewer]

library(shiny)

regional_sales <- c(North = 118000, South = 92000, East = 131000, West = 104000)

ui <- fluidPage(
  titlePanel("Vector indexing"),
  sidebarLayout(
    sidebarPanel(numericInput("cutoff", "Sales cutoff", value = 100000, min = 0)),
    mainPanel(tableOutput("selected"), verbatimTextOutput("named"))
  )
)

server <- function(input, output, session) {
  output$selected <- renderTable({
    regional_sales[regional_sales > input$cutoff]
  }, rownames = TRUE)

  output$named <- renderPrint({
    regional_sales["West"]
  })
}

shinyApp(ui, server)

Step 3: Data frames and missing values

The Goal: Work with rectangular business data while treating NA as unknown rather than zero. A data frame has rows and columns; the row grain must be stated before you summarize it.

The AI Prompt:

Create a three-row R data frame called orders with order_id, region, and revenue. Include one missing revenue value. Show how to count missing values and how to calculate a mean only after reporting the number of observed values. Explain why replacing NA with zero would be a business decision.

What to look for: Look for is.na(), sum(!is.na(revenue)), and an explicit na.rm = TRUE. A generated answer should not silently convert an unknown order to zero.

#| '!! shinylive warning !!': |
#|   shinylive does not work in self-contained HTML documents.
#|   Please set `embed-resources: false` in your metadata.
#| standalone: true
#| components: [editor, viewer]

library(shiny)

orders <- data.frame(
  order_id = c("A01", "A02", "A03", "A04"),
  region = c("North", "North", "West", "West"),
  revenue = c(80, NA, 45, 220)
)

ui <- fluidPage(
  titlePanel("Data frames and missingness"),
  sidebarLayout(
    sidebarPanel(checkboxInput("show_missing", "Show missing rows", value = TRUE)),
    mainPanel(verbatimTextOutput("metrics"), tableOutput("table"))
  )
)

server <- function(input, output, session) {
  output$metrics <- renderPrint({
    list(
      rows = nrow(orders),
      missing_revenue = sum(is.na(orders$revenue)),
      observed_revenue = sum(!is.na(orders$revenue)),
      mean_observed_revenue = mean(orders$revenue, na.rm = TRUE)
    )
  })

  output$table <- renderTable({
    if (isTRUE(input$show_missing)) orders else orders[!is.na(orders$revenue), ]
  })
}

shinyApp(ui, server)

Step 4: Functions and conditions

The Goal: Package a repeatable business rule into a function and handle edge cases such as a zero target. Functions make an AI-generated rule easier to test on several inputs.

The AI Prompt:

Write an R function called attainment that returns actual divided by target. If target is zero, return NA instead of Inf. Test it with two vectors and explain the difference between a vectorized condition and a single if statement.

What to look for: Look for an explicit zero-target rule and a vectorized result. Test both ordinary and edge-case inputs; do not accept a function merely because it returns a number for the happy path.

#| '!! shinylive warning !!': |
#|   shinylive does not work in self-contained HTML documents.
#|   Please set `embed-resources: false` in your metadata.
#| standalone: true
#| components: [editor, viewer]

library(shiny)

attainment <- function(actual, target) {
  ifelse(target == 0, NA_real_, actual / target)
}

test_cases <- data.frame(
  actual = c(90, 110, 50),
  target = c(100, 100, 0)
)

test_cases$attainment <- attainment(test_cases$actual, test_cases$target)

ui <- fluidPage(
  titlePanel("Function and edge-case lab"),
  mainPanel(
    tableOutput("results"),
    verbatimTextOutput("check")
  )
)

server <- function(input, output, session) {
  output$results <- renderTable(test_cases)
  output$check <- renderPrint({
    list(zero_target_result = test_cases$attainment[3], all_finite = all(is.finite(test_cases$attainment[-3])))
  })
}

shinyApp(ui, server)
