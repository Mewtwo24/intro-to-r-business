Project 2: Customer Value

Project brief

You are an analyst supporting a subscription business. The marketing team wants a simple, transparent customer-value segmentation that can be used to prioritize outreach.

This project increases complexity by moving from order-level records to customer-level features. The central review question is whether the code counts and summarizes at the correct level.

Business question

Which customers are Low, Core, or High value based on completed spending in the last twelve months, and how large is each segment?

Data contract

Ask the AI assistant to create a reproducible hypothetical data frame called orders with:

  • customer_id: character identifier;
  • order_date: Date;
  • order_value: numeric dollars; and
  • status: character order status.

Each row represents one order. The analysis should use completed orders only and should define a fixed analysis date so that the results can be reproduced.

Use these segment rules:

  • Low: total completed spend below 500;
  • Core: total completed spend from 500 through 1,999.99; and
  • High: total completed spend of 2,000 or more.

Exact prompt to use

Write a reproducible R analysis using dplyr for a hypothetical data frame named orders. Each row represents one order. The columns are customer_id as character, order_date as Date, order_value as numeric dollars, and status as character. Create a fixed analysis_date in the example and keep only completed orders in the twelve months ending on that date. Exclude or clearly report missing customer IDs and missing order values. Summarize total completed spend, order count, and average order value for each unique customer_id. Classify customers as Low when total spend is below 500, Core when total spend is from 500 through 1,999.99, and High when total spend is 2,000 or more. Return both a customer-level table and a segment summary with customer count, total spend, and average customer spend. Include checks for duplicate order IDs, unexpected status values, missing dates, and whether the segment thresholds cover every customer. Explain the transformations in plain English for a marketing manager.

What to inspect in the response

Focus on the difference between an order and a customer:

  • Is the segment assigned after grouping by customer_id?
  • Is order count counted before or after customer aggregation?
  • Are incomplete, cancelled, or returned orders treated consistently?
  • Is the twelve-month period inclusive and reproducible?
  • Is average order value different from average customer spend?
  • Are customers with missing IDs excluded from the segment table?
  • Are the threshold boundaries implemented exactly?

An AI tool may use n() when the requirement is a unique customer count. That is correct in the customer-level table only if one row has already been created per customer.

Testing protocol

Create a hand-check customer with three completed orders of 200, 150, and 200 dollars. The customer should have total spend of 550 and belong to the Core segment. Add a cancelled order and verify that it does not change the segment if the business definition says completed orders only.

Also inspect:

  • total rows before and after the date filter;
  • total customers before and after missing-ID handling;
  • the sum of segment customer counts;
  • the sum of segment spend; and
  • the minimum and maximum customer spend.

Deliverable

Prepare a marketing brief with:

  • the count and share of customers in each segment;
  • the total spend represented by each segment;
  • the definition of value used;
  • one action the marketing team could consider for each segment; and
  • one reason the segmentation should not be treated as a permanent customer identity.

Extension: compare threshold and quantile approaches

Ask the AI assistant to create a second version using quantiles rather than fixed dollar thresholds. Compare the interpretability, stability, and business usefulness of the two approaches. Explain which method you would recommend and why.
