Visual Analytics with ggplot2

Build a visual argument one grammar layer at a time

ggplot2 turns a table into a visual argument by layering data, mappings, geometries, scales, labels, and themes. Each step below adds one decision. Ask an AI assistant for the smallest change, run the result immediately, and review whether the new layer improves the business comparison or merely adds decoration.

The examples use mtcars, a built-in dataset with one row per car model. The business translation is deliberately simple: treat mpg as an efficiency measure, wt as vehicle weight, and cyl as a category.

Step 1: Build the base canvas with ggplot()

The Goal: Define the data and map variables to positions before choosing a geometry. The base canvas establishes the coordinate system and tells the reader what each position means.

The AI Prompt:

Create a ggplot2 base canvas using mtcars, with vehicle weight wt on the x-axis and miles per gallon mpg on the y-axis. Do not add a geometry yet. Explain what the x and y positions represent and what one row means.

What to look for: Look for ggplot(mtcars, aes(x = wt, y = mpg)). The data and aesthetics belong in the base plot. Without a geometry, the viewer should show the axes but no marks.

library(ggplot2)

  output$canvas <- renderPlot({
    ggplot(mtcars, aes(x = wt, y = mpg)) +
      geom_blank()
  })
}

shinyApp(ui, server)

Step 2: Add a geometry with geom_point()

The Goal: Convert rows into visible marks. geom_point() creates one point per observation, which is useful for examining a relationship between two numeric variables.

The AI Prompt:

Add geom_point() to a ggplot2 canvas that maps wt to x and mpg to y using mtcars. Add a title that describes the observed relationship without claiming causality. Explain what one point represents.

What to look for: Look for + geom_point() and a title that says association, pattern, or relationship rather than “weight causes low MPG.” Check for unusual points that an AI-generated story might ignore.

library(shiny)
library(ggplot2)

ui <- fluidPage(
  titlePanel("geom_point() lab"),
  mainPanel(plotOutput("scatter", height = "420px"))
)

server <- function(input, output, session) {
  output$scatter <- renderPlot({
    ggplot(mtcars, aes(x = wt, y = mpg)) +
      geom_point(size = 3, color = "#176B87") +
      labs(
        title = "Heavier vehicles tend to have lower fuel efficiency",
        x = "Weight (1,000 lb)",
        y = "Miles per gallon"
      )
  })
}

shinyApp(ui, server)

Step 3: Color by a meaningful variable

The Goal: Add a categorical variable to reveal whether the relationship differs by group. Mapping color inside aes() creates a legend and lets the data drive the visual encoding.

The AI Prompt:

Add cylinder count as a color mapping to the mtcars scatter plot. Treat cyl as a categorical variable, create a clear legend label, and explain whether color changes the data or only changes how the data is displayed.

What to look for: Look for color = factor(cyl) inside aes(), not a hard-coded color outside it. Check that the legend is understandable and that the grouping does not imply a causal mechanism.

library(shiny)
library(ggplot2)

ui <- fluidPage(
  titlePanel("Color mapping lab"),
  sidebarLayout(
    sidebarPanel(
      checkboxInput("trend", "Add a linear trend for exploration", value = FALSE),
      helpText("A trend line describes association; it does not prove cause.")
    ),
    mainPanel(plotOutput("colored", height = "420px"))
  )
)

server <- function(input, output, session) {
  output$colored <- renderPlot({
    p <- ggplot(mtcars, aes(x = wt, y = mpg, color = factor(cyl))) +
      geom_point(size = 3) +
      labs(color = "Cylinders", x = "Weight (1,000 lb)", y = "Miles per gallon")
    if (isTRUE(input$trend)) p <- p + geom_smooth(method = "lm", se = FALSE, color = "#555555")
    p
  })
}

shinyApp(ui, server)

Step 4: Add professional labels and themes

The Goal: Make the chart usable for a stakeholder. A publication-ready chart states the comparison, period or population, units, source, and any important limitation. Themes should support reading, not distract from the evidence.

The AI Prompt:

Refine this ggplot2 scatter plot for a business audience. Use a minimal theme, readable labels, a descriptive title, a subtitle naming the dataset and unit, and a caption stating that the relationship is descriptive. Do not change the data, scale, or analytical claim.

What to look for: Look for labs(), theme_minimal(), clear units, and a restrained design. Check that the title does not overclaim and that the formatting does not hide observations or truncate the comparison.

library(shiny)
library(ggplot2)

ui <- fluidPage(
  titlePanel("Professional styling lab"),
  sidebarLayout(
    sidebarPanel(
      radioButtons("version", "Version", choices = c("Draft", "Executive"), inline = TRUE),
      helpText("Compare the chart before and after the communication layer.")
    ),
    mainPanel(plotOutput("styled", height = "450px"))
  )
)

server <- function(input, output, session) {
  output$styled <- renderPlot({
    p <- ggplot(mtcars, aes(x = wt, y = mpg, color = factor(cyl))) +
      geom_point(size = 3)

    if (input$version == "Executive") {
      p <- p +
        labs(
          title = "Vehicle weight is associated with lower fuel efficiency",
          subtitle = "Motor Trend car data; one point per vehicle model",
          x = "Weight (1,000 lb)",
          y = "Miles per gallon",
          color = "Cylinders",
          caption = "Descriptive association; not evidence of causality"
        ) +
        theme_minimal(base_size = 12) +
        theme(panel.grid.minor = element_blank(), legend.position = "bottom")
    } else {
      p <- p + labs(x = "wt", y = "mpg", color = "cyl")
    }
    p
  })
}

shinyApp(ui, server)

Visualization review card

Ask your AI assistant to critique the final chart using four questions: What is the data grain? What does each position and color encode? Which visual claim is supported? Which claim would require additional evidence? Then write the stakeholder takeaway in plain English without mentioning ggplot() or geom_point().
