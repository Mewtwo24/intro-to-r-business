Verification, Debugging, and Sanity Checking

Treat errors and failed tests as evidence, not as interruptions

Debugging is the process of narrowing the difference between the intended analysis and the observed behavior. An AI assistant can shorten the search, but it cannot decide whether the intended behavior was correct. Your job is to preserve the evidence and ask for a root-cause analysis.

The complete debugging loop

  1. Run the smallest reproducible example. Reduce the data and code until the failure remains.
  2. Copy the complete error. Include the error class, message, and the line or call named in the traceback.
  3. Add context. Share the relevant code, object classes, dimensions, and expected behavior. Remove sensitive values.
  4. Ask for causes before fixes. Require two or three plausible causes, a test for each, and the smallest change.
  5. Apply one change. Do not accept a wholesale rewrite that makes it impossible to know what fixed the issue.
  6. Run acceptance tests. Confirm the original error is gone and the business meaning is unchanged.
  7. Record the lesson. Add the cause, fix, and prevention check to the prompt log.

Syntax errors versus logic errors

A syntax error prevents R from parsing or evaluating an expression. A logic error produces a result that looks reasonable but answers the wrong question.

Signal Likely category Example check
unexpected ')' Syntax Balance parentheses and commas
object 'x' not found Scope or naming Inspect object creation and spelling
could not find function Package or namespace Load the package or use pkg::fn()
Output has too many rows after a join Logic/grain Check key uniqueness and row counts
Result changes dramatically after na.rm = TRUE Data/method Report missing count and compare denominators
Plot is correct but misleadingly labeled Communication Compare title, scale, population, and metric

A root-cause prompt

Act as a debugging investigator, not a code generator.

Business intent: produce one row per customer with total completed-order revenue.
Expected row count: equal to the number of customer IDs in customers.

Code:
customers |> left_join(orders, by = "customer_id") |>
  group_by(customer_id) |> summarize(revenue = sum(order_value))

Complete error/output:
<paste the exact console output here>

Please return:
1. the most likely root cause;
2. two tests that would confirm or reject it;
3. the smallest code change;
4. one business-logic risk that could remain even if the code runs.
Do not rewrite the entire pipeline.

If the assistant proposes na.rm = TRUE, ask what population is being excluded and whether missing order values mean zero, unknown, or an invalid record. If it proposes inner_join(), ask which customers would disappear.

Sanity checks that belong in production code

stopifnot(nrow(customers) == n_distinct(customers$customer_id))

result <- customers |>
  left_join(orders, by = "customer_id") |>
  group_by(customer_id) |>
  summarize(
    revenue = sum(order_value, na.rm = TRUE),
    orders = n_distinct(order_id),
    .groups = "drop"
  )

stopifnot(nrow(result) == nrow(customers))
stopifnot(all(result$orders >= 0))

Tests should encode the business contract, not just implementation details. A test that passes because a column exists is weaker than a test that confirms the output has one row per customer and no negative completed-order counts.

Read the console like an investigator

Warnings are evidence. A warning about an unmatched join, a coercion, or removed rows can change the result without stopping execution. Copy the warning into the review log and decide whether it is expected. A clean console is not proof of a correct analysis; a noisy console is a request for an explanation.

Final review questions

  • Can another analyst reproduce the error from the shared snippet?
  • Did the fix address the root cause or merely suppress the message?
  • Did row count, grain, denominators, and missingness behavior change?
  • Does the corrected result pass a hand calculation on a tiny example?
  • Did the stakeholder summary change after the fix?
